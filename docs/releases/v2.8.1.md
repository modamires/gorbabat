# Gorbabat v2.8.1

## Scheduled mewMONEY! history

Price history is no longer demand-driven.

A dedicated Cloudflare Cron expression is now reserved for history:

`*/15 * * * *`

When Cloudflare invokes that exact trigger, the Worker:
1. fetches TGJU live directly;
2. fetches Milli, MelliGold and TalaSea live directly;
3. does NOT use fresh/stale economy cache for the persistent history snapshot;
4. calculates Smart average from those live results;
5. writes one atomic history batch to BOT_KV.

Every other existing Cron trigger continues to run the normal Daily-cat job.
This prevents adding a 15-minute trigger from accidentally sending Daily cats every 15 minutes.

## One KV write instead of five

History storage migrated from per-source v1 keys to one v2 batch key:

`economy:history:v2:all`

Each 15-minute snapshot contains all successful live sources plus Smart average:

```text
{
  t,
  sources: {
    tgju: {...},
    milli: {...},
    melligold: {...},
    talasea: {...},
    average: {...}
  }
}
```

Benefits:
- one KV write per 15-minute interval instead of up to five;
- all source prices share the same snapshot timestamp;
- less KV quota usage;
- less chance of source histories drifting apart.

At 96 intervals/day this is roughly 96 persistent history writes/day instead of roughly 480.

## Live-only persistent history

The scheduled collector uses direct source fetchers, not cached/stale wrappers.

If one external source fails:
- that source is omitted from that snapshot;
- successful sources are still stored;
- stale data is not inserted just to fill a gap.

This is preferable for chart integrity.

## API no longer writes persistent history

`/api/economy` is now read/display only regarding history.

This eliminates races between:
- user-driven Mini App refreshes
- scheduled cron history writes

The chart still merges the current raw card price as a temporary newest point in the UI.

## Migration compatibility

Old `economy:history:v1:<source>` data is read for up to the normal seven-day window and merged with v2 scheduled points.

New writes go only to:

`economy:history:v2:all`

So existing chart history does not suddenly disappear after deploy.

## Required Cloudflare change

After deploying v2.8.1, add this Cron Trigger in Cloudflare:

`*/15 * * * *`

Keep your existing Daily cron trigger(s) unchanged.

The Worker identifies the history trigger by its exact cron expression, so the new 15-minute trigger runs history only.
