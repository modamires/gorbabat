# Gorbabat v2.7.0 — Reliability & Debug Audit

This release is a broad hardening pass.

## Economy
- TGJU uses current deterministic pages (18K, 24K, XAU, coin category, currency, IQD, Brent).
- Added missing TGJU XAU mapping.
- TGJU outbound concurrency capped at 3.
- Source sanity checks reject implausible values and common x10/x100 unit mistakes.
- Default averaging now uses densest relative-price consensus, then MAD inside 3+ source consensus; standard deviation is not used.
- Two wildly conflicting sources are not blindly averaged; the higher-priority source wins.
- Fixed `null` change/changePercent accidentally becoming zero.
- Fresh cache plus 6-hour stale fallback per source; stale values remain subject to consensus/outlier filtering.
- English API errors; Mini App visible UI remains English except the requested Persian subtitle.
- Browser API request has a 15s AbortController timeout, validates JSON response type, and remembers source selection.
- Source count is shown even when only one source is available in Average mode; stale-cache usage is also surfaced in the source label.
- Added CSP and Permissions-Policy headers.

## Worker reliability
- In-isolate webhook update deduplication by Telegram update_id; failed handlers remove the marker so a retry is not suppressed.
- Voice, Twitter and heavy admin requests are awaited instead of relying on post-response waitUntil.
- All callback-query work is awaited.
- Qwen, GLM and Whisper have explicit timeouts.
- Voice download timeout + 12MB guard.
- Duck API timeout.
- KV PUT/DELETE now retry transient failures like GET/LIST.
- Direct BOT_KV mutations removed from runtime paths.
- Prefix deletes are concurrency-limited.
- Telegram parser handles non-JSON gateway responses and respects short 429 retry_after once without blindly retrying ambiguous send timeouts.
- Broadcast recipient concurrency capped at 6; duplicate/out-of-order continuation callbacks are rejected, with an additional in-isolate broadcast lock.
- Daily cat delivery concurrency reduced from 15 to 6 outbound sends per batch.
- Health score only applies CPU P99/error-rate penalties when there are at least 20 requests.
